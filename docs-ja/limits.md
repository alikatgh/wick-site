# 制限と機能台帳 { #limits-the-feature-ledger }

**基本原則: Wick に含めるのは本当に必要なものだけで、機能を持つこと自体を目的にしません。**
実際のゲームコードで、その機能がないために問題が生じたことを示せて初めて採用します。
それ以前には採用しません。並べて比較できるゲーム
（Lantern Night の Lua 版と Wick 版、Lantern 上の KORA）が、根拠を得る仕組みです。

## 機能の根拠台帳 { #feature-evidence-ledger }

| 候補 | 根拠 | 状態 |
|---|---|---|
| **レコード / 構造体** | KORA のキッチン: 5 本の並列な小物リスト | **採用済み** — フラットな `record`、`list<record>` |
| **ビット / バイトとワードのラップ** | プロセッサ制作ゲームと Bit Lab | **採用済み（0.3）** — 検査付き関数、16 進数・2 進数リテラル |
| 文字列の添字アクセス / 反復 | KORA の ASCII マップはオフラインで生成 | 記録済み — 事前生成で無理なく対応できる |
| クロージャ / 第一級関数 | まだなし | 候補 |
| ネストしたコンテナ | まれ | 候補 |
| 複数ファイルのモジュール | まだ単一の `main.wick` で問題なし | 候補 |
| 用途別のハンドル型（`tex`/`snd`） | ストアの第三者制作者 | 候補 |
| メソッド / クラス | — | 目標外 |

## 現在の制限（率直な一覧） { #current-limits-honest-table }

| まだない機能 | 現在の回避策 |
|---|---|
| クロージャ、ネストした関数、第一級関数 | トップレベルの `fn` + グローバル変数 |
| 複数の戻り値 | 2 つの関数、または別の状態を利用 |
| ネストしたコンテナ（`list<list<num>>`） | フラットなリスト上で添字を計算 |
| モジュール / インポート（単一の `main.wick`） | ゲームのスクリプト + データの事前生成ツール |
| `for x in list` による反復 | `for i in 0..len(xs)` |
| 文字列の添字アクセス / スライス / メソッド | `len`、`+`、`str()`。マップはオフラインで生成 |
| レコードやリストを持つレコードフィールド | 並列リスト、またはフラットな ID |
| 全実行経路での return の検査 | 戻り値の型がある関数の末尾にそのまま到達しないようにする |
| グローバル変数 / `and` の連鎖での型の絞り込み | `??`、または先にローカル変数へコピー |
| 指数表記の数値リテラル | 10 進数（0.3 以降は 16 進数・2 進数も利用可能） |

## 制限ではなく設計上の選択 { #choices-that-are-not-limits }

- **JIT なし** — 構造上 iOS の要件に適合し、静的な型から専用のバイトコードを生成します。
- **決定的な `rand()`** — 変化させたい場合は `srand` でシードを指定してください。
- **パスのサンドボックス** — 読み込みはゲームディレクトリの外に出られません。言語の制限ではなく、
  ストアに対するホストの保証です。
