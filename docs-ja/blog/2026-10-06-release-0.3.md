# Wick 0.3: ビットを使って作る { #wick-03-bits-you-can-build-with }

*2026 年 10 月 6 日 · Lantern 0.8.0 に同梱*

次のゲームでは、Intel 8080 を対象として、プレイヤーにプロセッサを作ってもらいます。
そのゲームを作る前に、Wick はプレイヤーが扱うものを記述できる必要があります。
ビット、8 ビットのレジスタ、16 ビットのアドレスです。

Wick 0.3 では、その作業に絞ったツールを追加しました。

- `0x` の 16 進数リテラルと `0b` の 2 進数リテラル。
- AND、OR、XOR、NOT、論理シフトを、検査付きの `bit_*` 関数として提供。
- バイトとワードを明示的にラップする `u8` と `u16`。
- レジスタやバスを読みやすく表示する `hex` と `bin`。

```wick
let a = 0xFF
let wide = a + 1
let carry = wide > 0xFF
a = u8(wide)
check(carry and hex(a, 2) == "00", "carry stays visible")
```

## 関数にした理由と、値を検査する理由 { #why-functions-and-why-checked-values }

言語にはすでに型付きのネイティブ呼び出しがあります。その仕組みを再利用することで、
コンパイラを小さく保ち、演算子の優先順位を新たに増やさずに済みます。
`bit_and` という呼び出しは処理を明確に表し、誤った引数の型はコンパイル時に検出されます。

Wick の数値型は引き続き 1 種類です。ビット関数は、倍精度浮動小数点数で正確に表せる
符号なし 32 ビット整数を受け入れます。小数、負のビット演算のオペランド、非有限値、
0〜31 の範囲外のシフトは Wick の実行時エラーになります。VM は C++ でキャストやシフトを
行う前に検査します。ホストの未定義動作は言語の機能ではありません。
レジスタでは負の数の算術演算が役立つため、`u8(-1)` は明示的に 255 になります。
ラップが受け入れるのは、安全な整数だけです。

書式設定は、切り詰めずに桁を埋めます。`hex(256, 2)` は `100` になるため、
幅が大きすぎる値が 2 文字のラベルの裏に隠れることはありません。

## 根拠となる Bit Lab { #the-evidence-bit-lab }

このリリースには、Wick で書いた小さな対話型のレジスタ / ALU 作業台、
[Bit Lab](https://github.com/alikatgh/lantern/tree/main/games/bitlab) が含まれます。
入力バイトを変更し、個々のビットを切り替え、ADD/AND/XOR を選び、結果とフラグを確認できます。
16 ビットのプログラムカウンタが FFFF から 0000 にラップする様子も示します。

これは、予定しているゲームに向けた最初の言語の実践例です。CPU 全体、その命令のタイミング、
プレイヤーのゲート回路をエミュレートするものではありません。
ゲームそのものは、引き続き次のプロジェクトです。

## テストと書籍 { #tests-and-the-book }

単体のコンパイラ / VM スイートは、正しい式、256 個すべてのバイト値、
64 Ki エントリのメモリ、不正なリテラル、符号なし値の境界、不正な数値入力、
書式の幅、ホットリロードを検査します。SDL なしで実行できます。
既存の言語、タッチ、パッケージ、パスのサンドボックスの各スイートも、引き続き回帰検査の条件です。
実際に行った検証の詳細は[リリース](https://github.com/alikatgh/lantern/releases/tag/v0.8.0)を参照してください。

書籍は 0.3 版になりました。既存の章でレコードを説明し、新しい章ではビット、バス、
レジスタペア、メモリ、加算器を順に扱います。Web 版と PDF の両方で、LaTeX のソースが
正本であることは変わりません。言語リファレンスには、
[新しい関数の完全な規約](../bits.md)を掲載しています。

インポート、ネストしたコンテナ、クロージャ、文字列の添字アクセスは、まだありません。
それらにはゲームからの根拠が必要です。このリリースでは、必要性をすでに示せる操作を追加しています。

**アップグレードの注意:** 新しい組み込み関数名（`bit_and`、`bit_or`、`bit_xor`、
`bit_not`、`bit_shl`、`bit_shr`、`u8`、`u16`、`hex`、`bin`）と同名のユーザー関数宣言は、
コンパイル時に拒否されます。名前が衝突する関数は改名してください。
依存関係や数値型の追加はありません。
