# ストアの安全性は言語の性質 { #store-safety-is-a-language-property }

*2026-07-14*

Lantern のストアは、ゲームを `.lant` パッケージとして提供します。説明は単純です。

> ストアのゲームができる最悪のことは、不快なピクセルを描くことだけです。

この説明が成り立つのは、**言語とホスト**がその性質を保証する場合だけです。
この記事では、単なる願望に終わらせないために塞いだ穴を説明します。

## Wick 専用のパッケージ { #wick-only-packages }

`lantern_pack` は `main.wick` のないフォルダを拒否します。Lua には `os` と `io` があります。
ローカル開発には適していますが、知らない人のコードを実行するためには適していません。
Wick が外部とやり取りできるのは、ホストが登録する型付きの `lt.*` ネイティブ関数だけです。
言語には、任意のファイルを開く API、シェル、ソケットはありません。

これは必要条件ですが、十分条件ではありません。

## パスのサンドボックス { #path-sandbox }

このリリースまでは、読み込みに次の処理を使っていました。

```text
path = gameDir + "/" + userString
```

Wick プログラムは `../` や絶対パスを渡して、ゲームフォルダの外を読み取ることができました。
また、`lt.screenshot` では外への書き込みもできました。

現在は Wick と Lua のすべての読み込み（`load_texture`、`load_mesh`、`load_sound`）が
`pathResolveUnder` を通ります。

- 絶対パスは使えません
- `..` を含むパス要素は使えません
- 隠しファイルとなる、ドットで始まるパス要素は使えません
- `assets/tileset.bmp` のような複数の要素からなる相対パスは使えます

拒否された場合は、エラー画面または stderr にホストエラー（`path refused: …`）が表示されます。
CI: `tests/path_sandbox_test.sh`。

## パッケージモードのスクリーンショット { #screenshots-in-package-mode }

ホストが `.lant` を一時ディレクトリに展開すると、**パッケージモード**になります。
`lt.screenshot` は、その展開先ディレクトリ内にベース名のみで書き込めます。
フォルダモードでの開発では、同じ相対パス規則に従って、引き続きゲームディレクトリ内に書き込めます。

## 階層のあるパッケージ名 { #nested-package-names }

KORA のアセットは `assets/` にあります。以前のパッケージ作成ツールは、サブディレクトリを
黙ってスキップしていたため、KORA の `.lant` はテクスチャなしで配布されてしまいました。
現在のパッケージは `/` を含む相対パスを格納し、展開時に親ディレクトリを作成します。
フラットな構成のゲーム（Lantern Night）は変わりません。

`LANTERN_FIXED_DT` を指定すると、フォルダ版とパッケージ版のキッチンのフレームは
**バイト単位で同一**になります。ほかのすべてと同じ決定性の基準です。

## 現在の「構造上安全」の意味 { #what-safe-by-construction-means-now }

| 保証 | 仕組み |
|---|---|
| ネットワーク / シェルなし | 言語に API がない |
| 任意のファイルを読めない | 読み込みにパスのサンドボックスを適用 |
| 任意のファイルに書けない | スクリーンショットのポリシーと、名前付きセーブ以外に書き込み用ネイティブ関数がないこと |
| セーブの範囲を制限 | アプリのサポート領域内で、`lt.save` の名前の文字をフィルタリング |
| レビューできる範囲 | Wick 専用のストアパッケージ |

ストアへの提出物は、引き続きレビューします。ホストの実際の動作が、説明に一致するようになりました。
