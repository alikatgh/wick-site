# Nyurgun：Wick で描く世界、人物、物語 { #nyurgun-painted-worlds-characters-and-story-in-wick }

*2026 年 10 月 12 日 · ローカル開発レポート*

Nyurgun は、Wick で制作している、物語を軸にしたサハのアクション探索ゲームです。
移動と戦闘は Castlevania、会話、持ち物、選択は Ultima に着想を得ています。
サハの文学と美術をゲームに生かし、人々、土地、選択によって物語を伝えることを目指しています。
制作の構想は、AI が全面的に制作し、人が作る作品に求める完成度で評価するゲームです。
統一された美術方針、個性ある人物、意味のある動き、丁寧に編集した物語と音を目指します。

物語の典拠は、オロスィン／エルギスの 1947 年版です。ローカルで動作する現在のゲームは、
第 IV〜V 章のアイタリー救出編を 5 地域にわたって描き、原典と照合した第 VI、VII、VIII 章の
エピソードへつなぎます。北への出発もその一部です。これは長い叙事詩の一部分です。
人物には、それぞれの関係や、助ける、抗う、去る理由を持って話し、行動する余地が必要です。

![Nyurgun の開発試作：絵画調の山岳風景、木々、登場人物](../assets/nyurgun/opening-development-2026-10-12.png)

*実際の Wick VM と Lantern のソフトウェアレンダラーを使い、ヘッドレス表示で取得した開発試作です。
ネイティブウィンドウでの検証ではありません。美術は制作途中です。*

## 絵の質感を描画まで保つ { #paint-that-survives-the-renderer }

目標は、選定したヤクートの叙事詩挿絵の画風です。表情のある顔、細かな衣装や金属細工、
奥行きのある風景を求めています。現在のゲームは、まだその水準に達していません。
読みやすくした Unicode 文字、多層の視差スクロール、地域地図、人物の肖像や動作ポーズは、
場面を読み取りやすくし、一人ひとりを描き分けるための取り組みです。

レンダラーは、ゲームの論理座標を 400×240 に保ち、実際の描画密度を
1〜4 に制限しています。ネイティブランチャーの設定は既定で 2、フレームバッファーは 800×480 です。
画素を増やして元の絵の細部を保ちますが、移動や地形の座標は変わりません。

美術データの処理では、明示的な BMP V4 アルファを、従来のマゼンタ色による透過方式と区別します。
アルファで重み付けしたバイリニア補間により柔らかな絵の輪郭を保ち、不透明画素の計算は従来と互換にしています。
書き出し検査では、15 枚のアルファ付きアトラスにある半透明画素 714,269 個を保持しました。

世界樹は、このプロジェクトで生成して保存していた小物の原画に由来します。原画の 224×224 の領域を
そのまま切り出し、余白を加えた 256×256 のアトラス区画へ、従来の 4 倍の密度で格納しました。
原画の細部を正確に保っており、拡大や新たな細部の生成は行っていません。
原画にある薄い縁取りは、今後の見た目の確認項目として残っています。

絵画のアルファを保つレンダラーは、[上流のプルリクエスト #2](https://github.com/alikatgh/lantern/pull/2) を通じて
Lantern の main ソースにマージされました。公開中の Lantern のダウンロードは引き続き 0.8.0 です。

## 人物の細部を取り戻す { #recovering-character-detail }

8 つの肖像区画と 4 つの準備ポーズについて、保存していたプロジェクト生成原画から、
従来の 4 倍のアトラス密度で細部を取り戻しました。人物の同一性、構図、ルートアンカーは保っています。
この改修で新しい美術やアニメーションは追加していません。

![Nyurgun の人物の細部の比較：左が従来のアトラス、右が細部を取り戻したもの](../assets/nyurgun/character-detail-comparison-2026-10-12.png)

*左が従来のアトラス、右が細部を取り戻したものです。どちらも同じ固定ヘッドレス状態から、
実際のゲームの描画処理で 2 フレームを実行し、実際の描画密度 4 で取得しました。
顔や鎧の細部は明瞭になりました。ネイティブ表示と最終的な見た目の品質は未確認です。*

## 脇役の細部を取り戻す { #recovering-the-supporting-cast }

プレイ中にも、顔、三つ編み、刺繍のある衣装を読み取れる必要があります。
第VI〜VIII章の人物アトラスの12区画について、保存していた3枚のプロジェクト生成原画から、
従来の4倍のアトラス密度で細部を取り戻しました。同じ人物、2人が一緒に描かれた受け渡し場面、
足元の基準点、歩行周期を保持しています。新しいポーズや人体の修正は加えていません。

![2人の受け渡し場面：左が従来のアトラス、右が元の絵の細部を取り戻したもの。](../assets/nyurgun/supporting-handover-detail-2026-10-12.png)

![歩くアイタリー：左が従来のアトラス、右が元の絵の細部を取り戻したもの。](../assets/nyurgun/supporting-walk-detail-2026-10-12.png)

*実際のゲームの描画関数を使い、固定状態を物理描画密度4で比較しています。
構図を変えずに原画の細部を復元した結果であり、ネイティブ環境での動きの品質を証明するものではありません。*

独立した再構成で原画由来のRGBA全チャンネルを比較し、取り込み時の28件の拒否検査と
24件の実際の描画検査で全12区画を左右両方向で確認しました。新たな独立レビューに加え、
新しい絵を使った実装済みの全行程も **通常入力11,934フレーム**で完了しました。

この後続のソース変更は、保存済みの0.4.6レビュー用アーカイブには含まれません。
冒頭の使者と救出編の人物は別の小物アトラスを使っており、細部の改善がまだ必要です。
アイタリーの1ポーズには、記録済みの顔の大きさの不一致と、隠れた腰・歩行の課題が残っています。
ネイティブでのプレイと、最終的な見た目・文化面の承認は未確認です。

## 救出編の人物の細部を取り戻す { #recovering-the-rescue-characters }

囚われたアイタリー、天からの使者、アイイ・ウムスールは、従来の詰め合わせ画像の4倍の密度を持つ
専用アトラスから描くようになりました。保存していた本プロジェクトの生成原画から、選択した画素を
拡大縮小せずにコピーしています。画面上の論理的な大きさと足元の位置は同じで、以前の小道具アトラスも保存しています。

![実際のゲームの人物描画関数で比較した、天からの使者の細部復元前と復元後。](../assets/nyurgun/rescue-messenger-detail-2026-10-12.png)

新しいマスクの規則では、非常に薄い画素、小さな別成分、原画の下側の切り出し境界を除くことを明記しました。
不明な従来のマスクを再現したものでも、人物の輪郭を完全に保持した証明でもありません。
3段階の描画密度での18件の実際の人物描画、独立した原画チャンネルの照合、独立レビューが通りました。
静止画の細部を改善した段階であり、アニメーションと最終的な文化面の確認は今後の作業です。

![細部を復元した使者を含む、状態を指定した冒頭場面。実際のWick VMとLantern描画器を使用し、OS表示はテスト用です。](../assets/nyurgun/rescue-opening-detail-2026-10-12.png)

**0.4.8のローカルMacレビュー候補**には、この3人と旅の地図を収録しました。
ビルド、署名、アーカイブの照合を終え、通常入力によるヘッドレスの通しプレイは描画密度1で再び11,934フレームを通過しました。
上の場面は状態を指定した描画検査であり、ネイティブウィンドウの画像ではありません。
権限が有効でもコンピューター操作への接続が失敗するため、ネイティブ環境のレビューは未完了です。
承認済みのAI音源はまだ同梱しておらず、叙事詩全体も未完成です。

## 叙事詩をたどる旅の地図 { #a-journey-atlas-for-the-epic }

旅の地図が、実装済みの第IV〜V章の救出編と第VI、VII、VIII章に対応しました。
章の一覧で物語の順序を示し、それぞれの地図に現在地、次に会う人物や目標、
絵画調の場面の切り抜きをまとめています。救出編の地図では、実際の5地域の地形と
目印を保持し、世界の中で道を探すために使えます。

![英語の第VI章の旅の地図。西の山々、現在地、次に対面するティミル・デーシンテイを示しています。](../assets/nyurgun/journey-atlas-vi-2026-10-12.png)

*組み立て済みのゲーム状態から、実際のWick VMとLanternレンダラーを使い、
物理描画密度2で描画した第VI章です。不透明のパネルと明瞭なHD文字により、
絵画調の背景の上でも地図を読み取れます。*

第VIII章では、現在のニュルグンの北への道と、サブィヤが語る過去を分けて示します。
まだ分からない距離や運命は不明のままとし、架空の地理や結末で補っていません。

![ロシア語の第VIII章の旅の地図。ニュルグンの北への道と、サブィヤが語る過去を別々に示しています。](../assets/nyurgun/journey-atlas-viii-2026-10-12.png)

*現在の旅と語られた過去を、地図内の別々の領域に表示しています。
状態を設定したヘッドレス画像であり、ネイティブ環境でのプレイではありません。*

新しい文言はサハ語、ロシア語、英語に対応しています。サハ語は、流暢な話者の確認を待つ草稿です。
組み立て済みのゲームを物理描画密度2で動かす、**3言語にわたる51件の状態設定済み描画検査**が通りました。
前の章の状態が残る場合、章を単独で復元する場合、文字の表示範囲も検査しています。
これらは、地図の状態を設定して行うヘッドレス検証です。

別途、実装済みの全行程は、通常入力で地図を開き、一時停止・再開する操作を含め、
セーブ処理を変えずにソフトウェア描画密度1で検査を通りました。
描画密度2での全行程の検査は第VI章で時間切れとなり、上記のHD描画検査で代替することはできません。

**0.4.7のローカルMacレビュー候補**は、ビルド、署名、アーカイブの照合を終えました。
公証は受けていません。権限を有効にしてもデスクトップ操作への接続に失敗したため、
新しいネイティブゲーム画面の表示成功と、ネイティブ環境でのプレイの動きやテンポは未確認です。
承認済みのAI音声・音楽は同梱しておらず、叙事詩全体の実装も未完了です。

## 統合した候補の確認 { #reviewing-the-integrated-candidate }

新しい **0.4.6 のローカル Mac レビュー候補**は、細部を復元した主人公の32ポーズ、剣と鞭のアトラス、第VI章の負傷・死亡ポーズの優先処理を、復元済みの背景とネイティブ音声ランタイムとともに収録します。変更していないゲームソースは、救出編から第VIII章までを **通常入力11,934フレーム**で完了しました。実際のパッケージから得た8枚の画像で、3言語のタイトルと会話、冒頭、地図を物理密度2で確認しました。独立した成果物レビューは、ソース、画像、署名、アーカイブのバイトと権限を照合しています。以前の候補は変更していません。

![実際の0.4.6パッケージをWick VMとLantern描画器で描いた英語の冒頭画面。OS入力はテスト用です。](../assets/nyurgun/painted-characters-candidate-2026-10-12.png)

これは未公証のローカルレビュー用アーカイブであり、一般公開のゲームリリースではありません。デスクトップ操作への接続は利用できず、0.4.6のネイティブ画面や実機音声の成功は未確認です。VoiceStudio/YuEによる完成音源、最終的な絵と文化面の承認、サハ語話者の確認、叙事詩全体の実装も未完了です。

## 主人公のポーズの細部を取り戻す { #recovering-main-character-poses }

主人公の全 32 ポーズで、元の R4 原画と回転動作の原画から従来の 2 倍のアトラス密度により
細部を取り戻しました。2048×512 のテクスチャでも、論理的な区画、足元の基準点、
フレーム番号と動作の時間は変わりません。すべて原寸以下の縮尺です。
従来の切り取りによる欠落や所有画素の除外は記録したまま保持しています。
原画の細部の復元であり、人体の修正やアニメーションの追加ではありません。

![待機ポーズ：左が従来のアトラス、右が細部を取り戻したもの](../assets/nyurgun/hero-idle-detail-comparison-2026-10-12.png)

![歩行ポーズ：左が従来のアトラス、右が細部を取り戻したもの](../assets/nyurgun/hero-walk-detail-comparison-2026-10-12.png)

*実際のゲームの描画処理と物理描画密度 2 で、同じ構図を比較しています。
固定ポーズの比較であり、ネイティブ環境でのアニメーション品質を証明するものではありません。*

独立した検査で従来のアトラスを正確に再構成し、各書き出しの RGBA 全 4,194,304 チャンネルを
比較して、取り込み時の 35 件の不正な入力を拒否しました。8 種類のポーズを左右両方向で描画した
16 件を比較し、基準点をずらす対照検査はすべて拒否しました。新たな独立レビューと
主担当による描画の再検査も通りました。

## 世界の絵の細部を取り戻す { #recovering-the-painted-worlds }

10 枚すべてのパノラマで、プロジェクト生成原画の領域をそのまま保持するようにしました。
取り込み時に 800×240 へ縮小する代わりに、960×288、1320×396、1600×480 の
テクスチャを使います。各領域の元の RGB 画素を保持し、古い書き出し画像の拡大は行っていません。
論理的な構図、カメラの動き、地形、人物の位置は変わりません。

独立した検査で原画の 5,469,600 画素を比較し、すべての原画と世界以外の書き出しを保持しました。
選択された入力は合計 13,033,476 バイトで、従来の 30 MiB 制限内です。
人物と操作画面を含む新旧の場面を、カメラ移動の両端で実際のレンダラーの描画密度 2 により比較しました。
筆致や崖の細部が見えるようになりました。人物のアニメーション、世界の構成、
ネイティブ表示は引き続き改善と確認が必要です。

## 空のセーブからの連続プレイ { #a-continuous-fresh-save-campaign }

実装済みの救出編 → VI → VII → VIII が、空の専用セーブ領域から連続した
11,934 フレームの検査を通りました。通常のキーボード入力で、変更していない Wick の
操作、戦闘、移動処理を動かしています。4 章すべてが通常のセーブを書き込み、警告はありません。
検証器は正規の組み立て済みソース、連続した章の順序、必要な 16 場面のキャプチャを確認します。

これは、実際の VM、レンダラー、音声ミキサーに模擬 OS 入力・表示・音声出力を組み合わせた
ヘッドレス検証です。ネイティブ環境でのプレイや、叙事詩全体のゲーム化を証明するものではありません。

新しいローカルの 0.4.5 レビュー用アプリは、Lantern main の音声機能とコンパイラ検査に、
細部を取り戻した世界を組み合わせています。リソースの一致、ARM64/macOS 15、署名、
実際に展開したアーカイブの検査を通りました。ランタイムの準備では、ハッシュを確認した
37 個のソース入力を再ビルドしてから、型を指定した音声 API を検査します。
古いアプリは保持しています。自動起動の試行は、Wick やゲームの初期化より前に、
macOS のアプリケーション登録処理で停止しました。ネイティブ環境でのプレイ成功は未確認で、
実行形式の一般公開版ではありません。

## ゲームで道具を確かめる { #a-game-that-makes-the-tools-answerable }

救出編と後続のエピソードでは、会話、持ち物、進行、操作案内、セーブを使います。
出発の場面には、受け止めと体勢を立て直す動作に続き、4 つの武装ポーズを加えました。
対象を絞った検査は、ゲーム処理を模擬コードに置き換えず、実際の Wick コンパイラ、VM、レンダラーを動かします。

その後の VI 章のソース修正では、剣や鞭を振っている途中でも、Nyurgun の負傷や死亡の
ポーズを優先するようにしました。24 件の絵を使った検査で、左右両方向、死亡状態の維持、
通常操作での再挑戦、負傷反応後の無敵時間中の攻撃を確認しました。同じ回帰検査は修正前の
ソースを拒否し、最終的な組み立て済みゲームは空のセーブから再び 11,934 フレームの
連続検査を通りました。これらはヘッドレス検証です。保持している 0.4.5 アプリには、
この後続の修正は含まれていません。

## 声と音楽をゲームに組み込む { #voices-and-music-belong-to-the-game }

[ネイティブ音声機能を Lantern の main に統合しました](https://github.com/alikatgh/lantern/pull/4)。
Wick から効果音、音楽、台詞を別々に扱い、再利用されないボイスハンドルで一時停止や
フェードアウトを指定できます。音楽のクロスフェードはミキサーのサンプル時刻に従います。
台詞が実際に聞こえる間は音楽を下げ、終了後に戻せます。
コールバック内ではファイル操作、メモリ確保、音声データの解放を行いません。

Nyurgun のソースは、字幕の正確なキー、人物、選択言語に対応する台詞を再生するようになりました。
次の台詞への移行やスキップでは前の声を終了し、ポーズや日誌の表示中は再生を止めます。
言語を変えると以前の言語の声を取り消します。後半の演出場面と場面ごとの音楽も同じ制御を使います。
任意の録音がなくても、文章の表示とゲームの進行は続きます。

声の制作には [VoiceStudio](https://github.com/debpalash/VoiceStudio)、音楽には
[YuE](https://github.com/multimodal-art-projection/YuE) を必須の制作ツールとして使います。
計画には 8 種の人物・語り手の演出方針、サハ語・ロシア語・英語を合わせた 219 件の台詞、
7 曲の音楽キューがあります。これは完成した演奏や演技ではなく制作計画です。
バージョンを固定したコマンドラインアダプターが、上限を設けた確認可能なジョブと由来の記録を準備します。
モデルのインストールや推論の開始、別の生成器への無断の置き換えは行いません。
初期の音楽制作契約は、YuE2 とは別に、元の YuE-v1 のソースとモデルを固定しています。

録音をアセットマニフェストに登録するには、試聴、編集、文化面、権利の確認が必要です。
パッケージ作成時には承認済みファイルのハッシュ、現在の字幕、生成されたローダーを照合し、
ネイティブ音声機能を持たないランタイムを拒否します。承認済みの AI 音声・音楽はまだ同梱していません。
公開中の Lantern 0.8.0 と保存済みの Nyurgun レビュー用アプリは変更していません。

実際のエンジンの検査では 594 件のアサーションと 12 件すべての CTest が通りました。
Nyurgun のソースでは、音声統合の 22 件のアサーション、エピソード開始の 154 ケース、
5,425 フレームの本番ゲームの自動プレイが通りました。これらは合成音声またはヘッドレス表示による検査です。
実機での音声再生、試聴品質、最終的な人物の演技は未検証です。
WAV は上限付きのメモリに展開します。ストリーミングと圧縮コーデックは今後の課題です。

## エージェント向けのコンパイル検査 { #an-agent-facing-compiler-check }

Lantern のソースには、エージェントやほかのツール向けに `lantern check --json game` を追加しました。
実際の Wick コンパイラと通常の実行時と同じ Lantern API シグネチャを使い、ウィンドウを開かず、
ゲームのトップレベルコードやネイティブ呼び出しを実行せずに検査します。
[コンパイラ検査の改修](https://github.com/alikatgh/lantern/pull/3)は、診断を含む単一の構造化 JSON 結果を返します。ソース入力の上限は 8 MiB、入れ子の深さは 256 です。
定数プールが 16 ビットのインデックス範囲を超えた場合は、値の折り返しを許さず拒否します。

これは、エージェントが直接使える道具へ向けた一歩です。決定論的なヘッドレススクリプト実行、
実行時の状態の調査、実行命令数の上限設定は今後の課題です。

ゲームの言語の土台はサハ語です。当面は英語とロシア語の文章を整え、サハ語の文言は流暢な話者による
確認を待っています。ネイティブ表示、ネイティブ環境での通しプレイ、文化的な正確さも確認が必要です。
この報告は、エンジンとゲームに実装した内容と目標とする品質の記録です。
人物のアニメーションと絵画調の美術は、引き続き磨いていきます。

## 64 ビットを既定にし、32 ビットも明示して選べるようにする { #64-bit-by-default-with-an-explicit-32-bit-choice }

Nyurgun は引き続き 2D ゲームです。現代のネイティブ 64 ビット環境に向けて、細部のある
絵画調の人物と世界、滑らかなアニメーション、奥行きのある動き、編集した音声を目指します。
昔のコンソール作品から学ぶのは制作の質です。バイナリのビット幅だけで表示の品質が決まるわけではありません。

最初の具体的な変更は、Wick と Lantern のビルド契約です。ネイティブ 64 ビットを既定にし、
対応するツールチェーンと依存ライブラリを用意した開発者は `-DWICK_HOST_BITS=32` を
明示して選べます。不一致は拒否します。Wick を直接組み込む場合にも同じ選択を検査します。
エージェントと開発者は `lantern --build-info --json` でコンパイル済みランタイムを調べられます。
ゲームを開いたりコードを実行したりする必要はありません。[リファレンス](../../types/#native-64-bit-builds-and-numeric-precision)も参照してください。

既存の `num` は検証したターゲットでは binary64 を使い、整数の精度は 53 ビットです。
正確な 64 ビット整数型は、別の言語機能として取り組む課題です。保持している Nyurgun
0.4.8 の Mac 実行ファイルはすでに ARM64 です。このソース変更ではアプリや ZIP を置き換えていません。
実際の 32 ビット版と Windows、Linux、Intel Mac のターゲット行列は未検証です。

現在ゲームを実行しているのは Lantern です。Ember32 は別の ARM7 仮想コンソールをモデル化しています。
提案している Ember64 のネイティブランタイム層で Nyurgun を動かすには、Wick、絵画調の RGBA
描画、音声、セーブの契約を維持する必要があります。この層と再利用可能なデスクトップランナーは
今後の計画です。公開済み機能とは扱っておらず、今回のビルド方針の変更によって新しい美術や
承認済みの録音を追加したわけでもありません。

## 元の細部を取り戻し、最初の門をわかりやすくする { #more-source-detail-and-a-readable-first-gate }

ローカル候補版 0.4.9 では、15 系統のアトラスで保存済みの絵の細部を取り戻しました。
再配置により、透明部分も含めてアトラスの画素数は 33,436,160 増えました。
27 件すべての美術契約に合格し、論理座標上の基準点とアニメーションの
時間配分は維持しています。10 枚の世界パノラマ、救出編の人物、世界樹は、すでに利用できる
元画像の細部を保持しています。すべての素材が 4K になったわけではありません。
幅 8,192 ピクセルの動作アトラスも、複数のポーズを並べた画像であり、8K の人物ではありません。

![ヘッドレスで取得した VI 章の決闘。サハ語の文章は未確認の草稿](../assets/nyurgun/vi-source-detail-2026-10-12.png)

*既定の描画密度 2 で検証したヘッドレス通しプレイの VI 章です。
サハ語の文言は、流暢な話者による確認前の草稿です。*

最初の門では、使者の手がかりや炉の炭を探す必要があるとき、その案内が表示されます。
物語上の前提条件は維持しています。通常の入力による 700 フレームの経路と、
各言語の案内表示 18 件に合格しました。既定密度 2 の固定した救出編→VI→VII→VIII の
通しプレイは 11,970 フレームで完了し、20 枚の画像と 4 回の地図からの復帰を記録しました。
保護対象のソースとリソースのバイト列は変わっていません。

![ヘッドレスで取得した最初の門付近の英語案内](../assets/nyurgun/opening-gate-guidance-2026-10-12.png)

*実際の Wick VM と Lantern の描画処理で取得した英語の門案内です。
OS の表示部分だけをテスト用に置き換えた、ヘッドレスの検証画像です。*

実際の VM によるフォント描画では、ラテン文字とサハ文字の違いを確かめる 84 組の検査に
合格しました。密度 2、3、6、9、10 と拡大文字を含みます。独立してラスタライズした
各密度の画像との比較で、RGB の各値の差は最大 1 でした。

[Lantern PR #6](https://github.com/alikatgh/lantern/pull/6) は main の `d59b521` に
マージされ、PR と main の CI、15 件すべての CTest、iOS のコンパイルとリンクに合格しました。
実験段階の描画処理はフレームバッファを最大 4,000×2,400 に制限し、密度 1〜10、
フレームバッファの大きさを調べる API、2D 描画の高速経路を追加しています。
ただし、4K の CPU 描画は転送前でも実測約 181 ms かかります。既定密度 2 は変えておらず、
4K 対応を完了したとはいえません。

署名済みのローカルアプリと ZIP/DMG パッケージはレビュー用です。アプリは正常に起動できておらず、
ネイティブ表示は未検証で、公証も受けていません。承認済みの AI 音声・音楽テイクは 0 件です。
ネイティブ環境でのプレイ、性能、文化的な確認、ゲーム全体の完成は今後の課題です。

## ワーカー数を制限して絵画調の世界を描画する { #rendering-painted-worlds-with-bounded-workers }

[Lantern PR #7](https://github.com/alikatgh/lantern/pull/7) は、明示して選べる絵画調の
2D 合成処理を追加します。アフィン変換による直接サンプリング、アルファ値を考慮した補間、
アトラスセル内へのサンプル制限を使います。常設のプールは最大 8 ワーカーに制限し、
作成に失敗すると逐次処理に戻ります。型付き Wick API は実際のモードとワーカー数を、
build-info はエージェントとパッケージ作成ツールに対応機能を示します。

地図画面は従来、不透明なパネルの背後の世界まで毎回描いていました。合成処理は後から
描く不透明な無地の長方形を一つ選び、先行描画の隠れる画素を省略します。見える外周、
アルファ値、描画順序は維持します。省略しない絵画調の描画とのバイト単位の比較 336 件には、
切り抜き、半透明・テクスチャ付きの覆い、変換を含む描画の境界を含めています。
テスト用表示で 16 件すべてのエンジン CTest に合格し、新たな独立レビューでも
未解決のコード指摘はありません。

ソースを変更しない検査では、実際の Wick VM、製品のコールバック、CPU 描画処理を使い、
通常入力で 1,848 フレームを実行します。英語・ロシア語のタイトル、冒頭のプレイ、地図は
1 ワーカーと 8 ワーカーで一致しました。計測中のソースと専用セーブは変わらず、
各画面のフレームバッファのダイジェストも最適化前と一致しました。

3600×2160、8 ワーカーでの最終 CPU 計測は次のとおりです。

| 画面 | 英語 中央値 / 95 パーセンタイル | ロシア語 中央値 / 95 パーセンタイル |
| --- | --- | --- |
| タイトル | 22.9 / 30.9 ms | 20.0 / 28.1 ms |
| 冒頭のプレイ | 35.0 / 48.7 ms | 30.4 / 48.5 ms |
| 地図 | 19.9 / 25.8 ms | 10.5 / 25.1 ms |

各条件は準備 30 フレーム、計測 120 フレームです。一台の開発用 Mac での値であり、
ネイティブ画面への転送と音声デバイスの処理は含みません。実行ごとに時間のばらつきが
ありました。覆われた地図を模した合成テストでは、同じ画像のまま中央値が 17.8 ms から
2.5 ms に短縮しましたが、実際のゲームはまだ 16.67 ms の予算を超えます。
ネイティブ環境で安定した 60 FPS を維持する作業は未完了です。

新しい Nyurgun パッケージは絵画調の合成処理を既定にし、固定したレビュー済みランタイムの
証明を必要とします。従来の描画処理を選ぶ明示的なオプションも残します。密度 2 と
ネイティブ解像度・密度の明示指定は維持します。保存済みの 0.4.9 アプリ、ZIP、DMG は
変更していません。

すべての 4K 美術も未完成です。この密度で論理座標 800×240 に描くスクロール用パノラマには、
約 7200×2160 の元画像が必要です。現在の画像を拡大しても細部は得られません。
既存のプロジェクト用会話での新しい絵、複数ページの動作アトラス、実測したテクスチャメモリ
予算、ネイティブ表示の確認が必要です。今回は新しい美術や承認済み AI 録音を追加していません。
