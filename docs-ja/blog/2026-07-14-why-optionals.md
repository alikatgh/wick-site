# オプショナルを採用した理由（実際のクラッシュ） { #why-optionals-a-real-crash }

*2026-07-14*

多くの言語は、型理論の流行からオプショナルを取り入れます。Wick が取り入れたきっかけは、
すでに人に見せていたゲームが最初のフレームでクラッシュしたことでした。

## Lua のバグ { #the-lua-bug }

Lantern Night はハイスコアを保存します。Lua 版では、よくある方法を使っていました。

```lua
local best = tonumber(lt.load_save("koranight_best") or "0")
```

セーブファイルが**存在しない**場合、`load_save` が失敗し、`or "0"` が機能します。
セーブファイルが**存在するものの空**の場合（書き込みの中断、0 バイト）、
`load_save` は `""` を返しました。Lua では `""` は真と判定されるため、フォールバックは
実行されませんでした。`tonumber("")` は `nil` です。続く算術演算が失敗しました。
単体テストでなく、実際の実行のタイトル画面で起きたことです。

これは仮定の話ではありません。Wick でオプショナルへの対処が任意ではない理由です。

## Wick での形 { #the-wick-shape }

```wick
let best = num(lt.load_save("koranight_wick_best") ?? "") ?? 0
```

- `lt.load_save` は `str?` を返します。セーブがなければ `nil` です。
- `?? ""` によって、`num(...)` に渡す値を必ず文字列にします。
- `num` は `num?` を返します。解析に失敗すると（`""` を含む）`nil` です。
- `?? 0` によって初めて、型が `num` になります。

この意図を表すプログラムで、コンパイラが受け入れる別の形はありません。
空文字列の場合を「忘れる」ことはできません。これが設計のすべてです。

## 採用しなかった方法 { #what-we-refused }

- ファイルがない場合も空の場合も `load_save` が `""` を返すようにする。2 つの場合を隠してしまいます。
- 実行時の null 検査だけを使う。すでにありましたが、省略できてしまいました。
- リンターの規則にする。リンターの使用は任意ですが、クラッシュはそうではありません。

## 型の絞り込み { #narrowing }

```wick
let s = lt.load_save("hi")
if s != nil {
  lt.print(s, 4, 4, 1, 1, 1, 1)  // s: str here
}
```

現在のコンパイラは 1 パスなので、型の絞り込みはローカル変数のみです。
グローバル変数には `??` を使います。これは実装の規模との兼ね合いであり、思想として禁止しているわけではありません。

## ここから分かること { #takeaway }

Wick のオプショナルは、「和型が欲しかった」からではありません。
**空のセーブファイルが、何も知らせずクラッシュする形を表現できなくした**ものです。
ほかの型の機能にも、同じ基準を求めます。
